# Fix Admin Dashboard: Dedup, Rename API Adapters, Move to Curated Section

## Problem Summary

The admin page at `/admin` (Data Pipeline & Queue section) has three issues:

1. **Duplication**: `api:worldbank` appears in the "Source Groups" section AND as "World Bank API" in the "Curated Data Sources" section — showing the same data source twice.

2. **Fuzzy naming**: The 6 new API adapters show ugly technical descriptions like `"Adapter: api:gcf (schedule: 0 4 * * 0)"` instead of human-readable names.

3. **Wrong section**: The new `api:*` adapters (api:gcf, api:dfc, api:afdb-energy, api:ifc, api:gem, api:aiddata) should be in the "Curated Data Sources" section alongside "World Bank API" and "Import Seed Data" — NOT mixed into the "Source Groups" section with the legacy scraper groups.

## Files to Edit

### File 1: `artifacts/api-server/src/routes/adapters.ts`

**Current code** (lines ~448-457):

**Replace with** — only seed DFI/RSS/Google Alerts adapters (not `api:*` ones, since those will be in the Curated section):
```typescript
    // Seed registered adapters that belong in Source Groups.
    // api:* adapters are shown in the "Curated Data Sources" section instead,
    // so we skip them here to avoid duplication.
    for (const adapter of ADAPTER_REGISTRY) {
      if (adapter.key.startsWith("api:")) continue; // shown in Curated section
      seen.set(adapter.key, {
        name: adapter.key,
        description: `Adapter: ${adapter.key} (schedule: ${adapter.schedule})`,
        feedCount: 1,
        isRunning: false,
      });
    }
```

This removes `api:worldbank`, `api:gcf`, `api:dfc`, `api:afdb-energy`, `api:ifc`, `api:gem`, and `api:aiddata` from the Source Groups response — they'll be shown in the Curated section instead.

**Also update the `runSpecial` call** in the button's `onClick` handler (around line 380). The current handler calls `runSpecial(endpoint, label)` which hits `/api/scraper/${endpoint}`. But the new API adapters need to hit `/api/adapters/${endpoint}/run` instead.

**Current button code** (~line 380):
```typescript
                <button onClick={() => runSpecial(endpoint, label)} disabled={!!specialRunning || !!runningSource} className={`...`}>
```

**Replace with** — route API adapters to the correct endpoint:
```typescript
                <button onClick={() => isAdapter ? runSource(endpoint) : runSpecial(endpoint, label)} disabled={!!specialRunning || !!runningSource} className={`...`}>
```

This way:
- "Import Seed Data" still calls `POST /api/scraper/seed` (via `runSpecial`)
- "World Bank API" still calls `POST /api/scraper/world-bank` (via `runSpecial`)
- All `api:*` adapters call `POST /api/adapters/${key}/run` (via `runSource`, which already handles adapter routing — see lines 298-305)
