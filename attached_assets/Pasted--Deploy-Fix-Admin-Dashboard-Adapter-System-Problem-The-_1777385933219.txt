# Deploy Fix: Admin Dashboard + Adapter System

## Problem
The admin page at afrienergytracker.io/admin still shows the old UI. All code fixes exist in the Replit workspace but the **frontend changes may not have been committed to GitHub**. Railway deploys from GitHub, so uncommitted frontend changes never reach production.

## Step-by-Step Fix

### Step 1: Verify all files are saved and correct

Check these 3 critical files have the correct content:

**File 1: `artifacts/api-server/src/routes/adapters.ts`**
Verify these sections exist:
- Line ~101: `const adapterKeys = ADAPTER_REGISTRY.map((a) => a.key);` (NOT `Object.keys(ADAPTER_REGISTRY)`)
- Line ~215: `const matchedAdapter = ADAPTER_REGISTRY.find((a) => a.key === sourceName);` (adapter fallback in legacy endpoint)
- Line ~450: The `for (const adapter of ADAPTER_REGISTRY)` loop that seeds the `seen` Map in GET `/scraper/sources`

**File 2: `artifacts/energy-tracker/src/pages/admin-dashboard.tsx`**
Verify the `runSource()` function (~line 293-305) contains:
```typescript
const isAdapter = sourceName !== "__all__" && sourceName.includes(":");
```

**File 3: `artifacts/api-server/src/scraper/adapters/index.ts`**

- `gcfApiAdapter` (api-gcf.ts)

### Step 2: Commit ALL changes to GitHub

Run these commands in the Replit Shell:

```bash

# Stage ALL changed files (both backend and frontend)
git add artifacts/api-server/src/routes/adapters.ts
git add artifacts/api-server/src/scraper/adapters/
git add artifacts/energy-tracker/src/pages/admin-dashboard.tsx

# Also stage any other modified files

# Commit
git commit -m "Fix adapter routing in admin dashboard and backend endpoints

- Frontend: route adapter keys (containing ':') to /api/adapters/:key/run endpoint

```

### Step 3: Verify Railway redeploy

After pushing:
1. Go to your Railway dashboard
2. Confirm a new deployment was triggered
3. Wait for it to go green (usually 2-3 minutes)

### Step 4: Hard refresh the browser

After Railway deploys:
1. Go to afrienergytracker.io/admin
2. Hard refresh: **Ctrl+Shift+R** (Windows) or **Cmd+Shift+R** (Mac)
3. If still old, open DevTools (F12) > Application > Storage > Clear site data

### What you should see after deployment

The admin page at /admin should show:
- All 6 new structured adapters listed in the source groups (api:gcf, api:dfc, api:afdb-energy, api:ifc, api:gem, api:aiddata)
- Plus the existing adapters (dfi:afdb, dfi:ifc, dfi:dfc, etc.)
- Clicking "Run" on any adapter should work without "Unknown source group" errors
- "Run All Sources" should process both legacy source groups AND adapters sequentially

### Troubleshooting

**If adapters still don't appear after deploy:**
Check the API directly: `curl https://afrienergytracker.io/api/adapters`
- Should return JSON array with all adapter keys
- If it does but the UI doesn't show them, it's a frontend caching issue

**If "Run" still gives errors:**
Check: `curl -X POST https://afrienergytracker.io/api/adapters/api:gcf/run`
- Should return SSE stream (text/event-stream)
- If 404, the route isn't mounted properly

**If Railway build fails:**
Check build logs for errors. Common issues:
- Missing adapter source files (api-afdb-energy.ts, api-gem.ts, etc.)
- TypeScript compilation errors in new adapter files
- Missing imports in adapters/index.ts
